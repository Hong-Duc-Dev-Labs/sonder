# Phase 5: DSD playback

## What happened

- `sonder-decode::dsd` now reads DSF and uncompressed DSDIFF: DSF block deinterleaving and
  LSB-first bit reversal, DFF big-endian chunk parsing, chunk-size validation before
  allocation, DST rejected. `SourceDecoder` sniffs the magic and exposes a common timeline.
- `sonder-engine::dop` packs interleaved DSD bytes for DoP (2 bytes/channel/frame) and native
  ALSA DSD (4 bytes/channel big-endian word). The renderer writes the 0x05/0xFA markers at
  device-write time and emits 0x69 0x69 idle frames for underrun, pause, drain and stop, so
  the marker phase cannot break.
- `sonder-output` gained `SampleContainer::DsdU32Be`, `negotiate_dop`, `negotiate_native`,
  BM-format packing, and DSD idle handling in the shared renderer; ALSA now probes and opens
  `DSD_U32_BE`, WASAPI/CoreAudio reject native DSD and support DoP.
- `sonder-dsp` (new crate) converts DSD64/128/256 to 176.4/352.8 kHz with two Kaiser
  decimation stages; coefficient tables are generated by `build.rs`.
- Engine: per-device `DsdMode` (Dop/Native/Pcm), DSD lap with no f64 for DoP/native, DSD→PCM
  fallback with a `DsdMode` event reason, gapless same-rate DSD, DoP marker continuity.

## Decision

- DoP marker phase lives in the output renderer, the only device-buffer writer; a packer that
  stamped markers ahead of time cannot stay in phase when idle frames are inserted.
- Native DSD on ALSA uses the word rate `DSD bits / 32` (MPD convention) with big-endian
  words carrying four DSD bytes per channel.
- Active PCM stages disable DoP/native and force DSD→PCM with the reason reported; no DSP can
  corrupt a bit-perfect DoP stream.
- Phase 6's shared FIR core does not exist yet, so DSD→PCM ships its own build-time tables in
  `sonder-dsp`; phase 6 should port it onto `FirCore`.

## Verification

- `cargo test --workspace`: pass (including DoP round-trip == source bytes, gapless DSD,
  native DSD words, exact DSD→PCM device bytes, marker alternation across underrun/pause).
- `cargo clippy --workspace --all-targets -- -D warnings`: pass.
- `cargo fmt --all -- --check`: pass.
- ALSA/macOS sources were rustfmt-parsed but not compiled here (Windows host, cross
  pkg-config missing); ALSA native DSD needs the manual DAC test.

## Review fixes

- Gapless DSD tracks and seeks on ALSA fell back to PCM: the DoP probe ran while our own
  stream held `hw:` (EBUSY) and the error read as "unsupported". Now an open DSD stream is
  reused, probe errors are "unknown", and a rejected assumption re-decodes the track once.
- The stop idle period on ALSA was discarded by `drop()`; WASAPI wrote idle into a full
  buffer; CoreAudio had none. All three now end a stopped DSD stream on idle frames.
- CoreAudio's channel-mismatch cycle wrote zeros into DoP; it now writes DSD idle.
- DSF files with an unpadded last block group no longer read past the data chunk.

## Next steps

- Manual DoP test on a real DAC (DAC shows DSD64/128) and native-ALSA test on Linux.
- Measure DSD256→176.4k CPU headroom; consider symmetric-FIR optimisation.
- Phase 6: reuse `FirCore` for DSD→PCM instead of a second decimator implementation.
